## 三项指标的精确定义

全部指标在同一批原始输入文本上计算，编码不加BOS/EOS/PAD，特殊ID只计入总词表预算。

| 名称 | 计算 | 解释及边界 |
|---|---|---|
| tokenizer compression | 所有公式UTF-8字节数之和 / 所有公式输出token数之和 | 越高表示同一原文更短；是总量之比，不是逐公式比值的平均；不是文件压缩率，也不是模型准确率 |
| operation (%) | 100×内部无token边界的LaTeX命令数 / 命令总数 | 命令匹配反斜杠加ASCII字母，例如 `\partial`、`\sin`、`\cdot`；反斜杠与命令名之间切开即失败；不是所有数学运算符识别率，也不检查语义。命令整体并入更长token仍算完整 |
| numbers (%) | 100×内部无token边界的数字串数 / 数字串总数 | 数字串按 `[0-9]+(?:\.[0-9]+)?` 匹配；不含负号，科学计数法也不当整体；整体并入更长token仍算完整 |

同一划分内各方法必须用相同测试ID和相同指标分母；每条输入验证token字节拼接与decode均精确还原。分母为零时记N/A。三折总汇合并原始计数后再计算比例，避免把不同折的百分比简单平均。

## 当前benchmark迁移前已经确认的情况

目前有嵌套的212/636两档，原212保持不变。建议主输入采用未增强的 `structure_to_latex(gre_ids)`：它与当前下游Hard词表实际训练的文本一致。424条新增记录的文献原文可能保留系数、其他记号和上下文，不能与旧212的GRE渲染文本直接混成一个表示一致的主测试集。若另测原文，应独立命名并解释文本来源差异。

数据检查见 [benchmark_readiness.json](benchmark_readiness.json)：

- 212条：来源组只有1个；203种精确渲染文本，另有结构层面的重复。不能把同一来源组拆开后声称完成了旧协议的来源隔离三折或8:1:1。
- 636条：179个来源组，其中原212仍是一个大组。可以先构造来源/结构连接组再检查划分可行性，实际比例由组大小决定，不预先承诺恰好8:1:1。
- 两档GRE渲染文本中的数字词法单元全部是单个数字。按原指标，任何精确字节编码都无法在单个ASCII数字内部再切，因此numbers会恒为100%；应保留并披露这一退化，不人为加入长数字来改变当前benchmark。
- 636条有627种精确渲染文本。必须先计算统一结构键，将相同/约定等价结构及其增强排列归入同一组；仅按文本哈希不足以阻止结构泄漏。
- 若采用32倍增强，必须先按未增强源公式确定划分，增强只能在训练侧且不能跨组。主上游指标建议直接测未增强源公式，避免把相同公式排列重复计权。

## 可供决定的迁移方案

| 选项 | 具体做法 | 可回答的问题 |
|---|---|---|
| A：当前下游词表的全量诊断 | 直接加载212/636已有Hard280/315/350词表，在各自未增强benchmark上评估；通用分词器用相同文本 | 描述实际下游词表的压缩与完整性；词表见过全部语料，必须标为训练内诊断，不称未见公式泛化 |
| B：来源/结构隔离主实验 | 以636为主，按来源和结构连接组建立固定训练/验证/测试，重新仅在训练集学习Hard280/315/350；加入3种固定通用分词器 | 迁移旧8:1:1的处理方法，评估未见组表现；比例需先审核；原212来源组不可拆 |
| C：结构隔离的212小语料实验 | 对212按结构组划分，重新训练Hard280/315/350，使用相同3指标 | 可测未见结构，但来源相同；不能称来源外推，样本较小 |
| D：简单→复杂补充实验 | 先固定可复算的复杂度定义和阈值，再按组切分，简单训练、复杂测试 | 迁移旧复杂度评估；当前源记录不统一提供旧版complexity_bin，必须先补元数据和可行性审核 |
| E：容量/基础表扩展 | 可先只测当前280/315/350和当前98基础字节；若研究字符表，再单独恢复旧12容量或6×22矩阵 | 前者紧贴当前下游，后者是额外消融，范围由用户决定 |

上游旧主实验比较的是Hard与Qwen2.5、Llama 3、o200k_base，不含EqGPT GRE。GRE只能表示固定公式语法，decode输出规范化LaTeX，不能逐字节还原任意原始LaTeX，因此不能直接接入要求精确原文字节边界的旧measure函数。若要比较GRE序列长度，应单列结构表示长度诊断，统一语义/渲染口径，不冒充原三指标的一列。

建议先决定：评估212、636还是两档；希望诊断现有下游词表还是重新划分测泛化；是否保留3个通用分词器；容量只用280/315/350还是恢复旧扫描。确认后才冻结划分、训练词表并运行。大语料的上游分词评估不涉及下游Transformer或PDE搜索训练。
