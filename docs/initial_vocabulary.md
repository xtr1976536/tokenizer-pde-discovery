# 初始词表如何缩小

早期讨论中的1024是训练完成后的总词表预算。这里记录的是BPE学习合并前，初始词表占用的ID如何缩小。

## 从完整字节表到任务字符表

底层字节BPE训练器以全部256种单字节值为基础。PDE统一LaTeX文本采用ASCII记号，当前主配置将对外基础表固定为：

- 95个可打印ASCII字符：字节32–126；
- TAB、LF、CR三个空白字符：字节9、10、13。

因此，初始内容词表从256项缩至98项，回收158个单字节槽位。PAD、EOS、BOS另占3个ID：

| 初始组成 | 完整字节表 | 当前固定基础表 |
|---|---:|---:|
| 单字节内容项 | 256 | 98 |
| 控制符 | 3 | 3 |
| 初始占用总ID | 259 | 101 |

98是预先声明的字符集合。训练文本先检查字符覆盖，编码时遇到集合外的字节会明确报错。训练、验证、测试均核对解码还原。

## 为什么这些字节可以移除

依据是当前统一LaTeX的表示范围：训练器接收的是ASCII命令和符号组成的文本。声明集合之外的字节没有出现在这些训练文本中，不参与这些文本的BPE合并，因此其基础ID可以从模型对外词表回收。实际编码时仍检查字符覆盖，并验证编码、解码能精确还原输入。

例如，数学符号可以使用下列ASCII写法：

| 数学符号 | LaTeX文本 |
|---|---|
| α | `\alpha` |
| β | `\beta` |
| ∂ | `\partial` |
| ∇ | `\nabla` |
| Δ | `\Delta` |
| × | `\times` |

希腊字母和数学符号的含义保留在命令中；基础表只需表示英文字母、反斜杠、括号、数字等ASCII字符。后续BPE可以将完整命令学习为一个token。这些例子说明字符编码方式，具体公式能否进入PDE模型还取决于其公式语法和算子词表。

## 移除了哪些字节

| 移除范围 | 数量 | 例子 |
|---|---:|---|
| 字节0–31，除TAB/LF/CR | 29 | `0x00` NUL空字符、`0x07` BEL响铃、`0x08` BS退格、`0x1B` ESC终端转义 |
| 字节127 | 1 | `0x7F` DEL删除控制符 |
| 字节128–255 | 128 | UTF-8非ASCII字符使用的高位字节 |
| 合计 | 158 | 256 − 158 = 98 |

高位字节不等于独立字符。例如，`α`的UTF-8编码是`0xCE 0xB1`，而`\alpha`由六个ASCII字节组成；`∂`使用`0xE2 0x88 0x82`，而`\partial`同样只使用ASCII字节。当前基础表保留命令写法所需的字节。LaTeX反斜杠`\`是`0x5C`，与被移除的ESC字节`0x1B`不同。

## 适用范围

这项缩减适用于当前统一生成的ASCII LaTeX。任意LaTeX文件也可能直接包含`α`、中文或其他Unicode字符；这类输入需要先声明相应字符范围并重新检查覆盖，当前98字符编码器会拒绝集合外字节。

这里回收的是输入协议之外的基础字节槽位。训练得到的合并token即使最终输出次数为零，也可能是后续合并的中间步骤，需保留其规则依赖。

## 取消额外的预留词项

当前Hard AST-BPE调用训练器时，设置`atom_budget=0`、`subtree_budget=0`。完整LaTeX命令和公式子树不额外占用初始ID；它们由后续受AST边界约束的BPE合并学习得到。因此，当前初始内容词表就是上述98个单字节项。

## 用紧凑映射暴露模型ID

`CompactAlphabet`保留底层训练器的256字节结构，对外执行三步：

1. 保留声明字符表内的单字节项，以及训练得到的多字节项。
2. 过滤声明表之外的单字节项，并把保留项映射为连续内容ID。
3. Transformer适配器添加3个控制ID，内容ID统一偏移3。

训练预算同时补偿内部保留、对外回收的字节槽位，使最终对外词表按指定总容量构建。合并规则与token字节内容沿用底层结果；新的ID映射在Transformer训练前固定。

当前上游主实验AST-BPE256，以及下游212/636两档的Hard280/315/350，均采用98字符基础表。更小基础表的对照保留在上游词表容量实验中。
